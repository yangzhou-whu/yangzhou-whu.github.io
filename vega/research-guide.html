VEGA LAB / RESEARCH GUIDE

本科生科研入门指南

VEGA Lab · 武汉大学计算机学院

从一个具体问题开始，读懂论文、跑通代码、设计实验，再用结果支持自己的判断。Codex、Claude Code 可以协助阅读、编程和分析；研究问题、实验依据与最终结论，需要由你理解和核验。

第一个项目以完成以下三项成果为目标：

  • 两篇论文精读 讲清问题、方法与关键证据。
  • 一项代码复现 保存配置、日志与结果对照。
  • 一组对照实验 检验一个具体假设。

已有基础可直接从选题和代码开始；初学者先搭建 Linux 环境，完成一个小型训练与评估任务，再按四周安排推进。

01研究方向与选题

VEGA Lab 关注健康与生命科学中的人工智能。以下四条主线提供选题入口，每个方向附入门任务与 Nature、Science 系列期刊的补充阅读。先选一条主线，不必同时学习所有方向。

医学多模态基础模型 · Foundation

医学数据包含影像、文本等不同模态。我们关注模型如何利用这些数据学习可迁移的表征，以及如何在标注有限时适应新的任务。MerMED-FM [1] 研究多模态、多疾病医学影像基础模型，UrFound [2] 关注视网膜基础模型。

入门任务选择一个分类任务，比较预训练特征上的线性分类器与小规模微调，观察标注量变化对结果的影响。

补充阅读RETFound [3] 关注视网膜自监督预训练；Ark+ [4] 从多套胸片专家标注中积累知识；PanDerm [5] 学习多类皮肤影像表征；Merlin [6] 联合三维 CT、放射报告和电子病历建模。比较它们的监督信号、迁移任务与外部验证方式。

医学证据定位 · Grounding

模型给出判断或生成描述时，应当能够指出相应的图像区域或文本依据。MedRPG [7] 研究医学短语定位，EVLF-FM [8] 结合医学视觉语言建模与视觉证据定位。

入门任务检查定位区域是否支持对应描述，整理定位错误、遗漏异常和无证据描述的案例，提出一个有针对性的改进。

补充阅读MedSAM [9] 研究提示驱动的医学分割；UniBiomed [10] 联合生成诊断描述与目标分割；MedSegX [11] 研究开放世界医学分割。区分框定位、像素分割与文本证据对齐，检查模型在新模态、新器官上的表现。

医学大语言模型及智能体

从医学文本生成出发，进一步研究多轮问诊、知识检索和工具调用。Teaser [12] 按主题检索句子来生成医学报告；Note2Chat [13] 利用医疗笔记构建训练对话，提升多轮病史采集能力。两者分别提供报告生成与对话建模的入口；智能体进一步涉及规划和工具调用。

入门任务用获准使用的病例或模拟病例，比较两种问诊策略的信息完整性、重复提问和无依据推断，或检查报告中的异常遗漏。保存对话轨迹、检索证据和评分依据。

补充阅读AMIE [14] 研究多次就诊中的管理推理与对话，结合临床指南和药物知识；DeepRare [15] 结合多个智能体、专业工具与知识来源，支持罕见病鉴别诊断。重点看证据追踪与评测设置，区分模拟评测与真实临床应用的证据。

生信与生理信号大模型

研究数据从 DNA、RNA 和蛋白质序列延伸到睡眠、生理信号及可穿戴设备记录。ComBodied Agents [16] 提出以人为中心的智能体框架，讨论持续感知、长期记忆与个体状态建模，适合启发可穿戴数据相关选题；其中的框架设想与已完成的实验验证应分开理解。

入门任务用公开且获准使用的数据，比较简单基线与预训练表征，完成序列分类或生理时间序列预测。检查时间戳、缺失值、采样频率与个体差异，按受试者及时间划分数据，避免相邻片段泄漏到测试集。

补充阅读Biomni [17] 调用工具执行生物医学研究任务；SleepFM [18] 从多导睡眠监测信号学习表征并预测疾病；LucaOne [19] 联合建模核酸与蛋白质序列。SleepFM 迁移到日常可穿戴设备时，还需验证传感器差异与泛化能力。

选定主线后，先精读一篇相关论文，再补读一篇直接相关的基线或后续工作。结合数据、代码、模型权重和算力的可获得性，与导师确定第一个项目的范围。更多论文见周阳老师主页。

02开始前的准备

以 Linux 为主要开发和实验环境

科研代码、依赖安装和运行脚本优先在 Linux 环境中完成，便于迁移到实验室服务器。Linux 用户可直接开发；Windows 用户建议使用 WSL 2 中的 Ubuntu；macOS 用户可以在本地编辑代码，通过 SSH 连接 Linux 服务器运行实验。环境搭建可参考 MIT Missing Semester 2026：开发环境与工具（社区中译）。

基本配置为“编辑器或终端 + Git + conda 环境 + PyTorch”。VS Code 可连接 WSL 或远程 Linux 主机。复现时遵循作者仓库的 Python、PyTorch 和 CUDA 兼容要求，先跑通原有环境，再考虑升级依赖。

开始实验前，应能完成以下操作：

  • 在终端中查看路径和文件，理解相对路径、文件权限、管道和输出重定向。
  • 使用 Git 拉取代码、查看差异、提交和回退；将原始数据、权重和密钥排除在代码仓库之外。
  • 用 SSH 登录获准使用的服务器，在服务器上检查 Python 环境；NVIDIA GPU 环境用 nvidia-smi 查看显存和进程。
  • 在允许的远程服务器上用 tmux 管理会话，将参数写入配置文件，用脚本启动实验并保存日志；遵守共享 GPU 的使用安排。

Linux 环境不要求自购 GPU。先在 CPU 上检查数据和代码，再将同一项目放到服务器或下文的免费 GPU Notebook 平台上运行。Notebook 用于探索和小规模练习，正式实验尽量整理成可重复执行的脚本。

用 conda 隔离项目环境

conda 管理软件包与虚拟环境。每个环境拥有独立的 Python 和依赖版本，避免不同项目互相冲突。建议一篇论文或一个项目使用一个环境，实验依赖不要装进 base；环境隔离不负责数据隔离或 GPU 分配。

在 Linux、WSL 或服务器中使用该系统内安装的 conda，先运行 conda --version 检查是否可用。下面以 Python 3.11 为例；实际版本按作者仓库要求选择。若仓库已有 environment.yml，优先按其说明重建环境。

# 创建并进入项目环境
conda create -n vega-research python=3.11 pip
conda activate vega-research
python --version
which python

# 仅在仓库提供 requirements.txt 时执行
python -m pip install -r requirements.txt

# 保存环境和 pip 包版本，随实验材料归档
conda env export --no-builds > environment.yml
python -m pip freeze > requirements-frozen.txt
conda deactivate

# 在另一台兼容的 Linux 机器上重建
conda env create -n vega-reproduce -f environment.yml
conda activate vega-reproduce

导出前检查当前环境名称，分享前去掉 environment.yml 中指向本机的 prefix 路径，检查本地包路径和私有源地址。完整导出有助于记录一次运行；跨系统迁移时，可另用 conda env export --from-history 保存显式安装的 conda 依赖，并单独补齐 pip 依赖。任何导出文件都要经过实际重建验证。

PyTorch 与 CUDA 按仓库和官方安装说明配置，conda 环境不能替代主机 NVIDIA 驱动。在 Notebook 中还要选择对应的 Python 内核。让 Codex 或 Claude Code 运行实验时，明确环境名，并要求它先报告解释器路径；也可用 conda run -n vega-research python train.py 指定环境，其中脚本名按项目替换。

基础知识掌握到什么程度

学习基础知识与动手实践可以同时进行。先找出当前任务需要的概念，在代码中观察它们如何工作，再逐步补足理论。

基础需要掌握的内容
Python 与 PyTorch张量形状、数据加载、前向传播、损失与反向传播；训练模式和评估模式的区别
数学与机器学习向量和矩阵运算、梯度、过拟合、数据划分，以及评价指标的含义
视觉与语言模型按选题学习 CNN、ViT、Transformer、对比学习和预训练；需要模型适配时再学习指令微调与 LoRA
实验环境创建独立环境，用 Git 查看和回退修改；使用服务器时掌握 SSH、显存检查和日志保存
文献与表达查找原论文和作者代码，管理引用，用简短文字和图表说明问题与结果

完成一个小型训练、验证和测试任务，尝试解释每一步的数据形状与计算过程。学习资料按下一节选用，不必一次学完全部课程。

配置一个 AI 编程助手

选择 Codex 或 Claude Code，在项目目录中开始工作。它们可以结合项目文件理解任务、修改代码、执行命令和检查结果，具体能力取决于环境与权限。把论文、README、运行环境和预算交代清楚，每次完成一个可以检查的小任务。操作方法见 Codex 官方文档和 Claude Code 官方文档。

用 arXiv 和 Google Scholar 找论文

arXiv 是开放的学术预印本平台，适合追踪人工智能领域的新工作。按题名、作者或关键词检索，在摘要页查看提交时间、版本历史、PDF、代码链接以及可能存在的期刊信息。预印本上架不等于完成同行评审；阅读笔记应记录具体版本，如 v1 或 v2，避免将不同版本的实验混用。平台性质见 arXiv 官方介绍。

Google Scholar（谷歌学术） 是学术搜索引擎，可跨出版商和预印本平台查找论文。用英文任务词组合检索，例如 medical image grounding；用完整题名加引号寻找已知论文。通过“被引用”追踪后续工作，通过“所有版本”寻找作者公开稿，按年份筛选近期文献，并为需要持续跟进的主题设置提醒。引用计数只作线索，仍需阅读方法与实验；检索功能见 Google Scholar 官方帮助。

一次完整检索练习：从本指南选一篇论文，在 Google Scholar 找到一篇相关后续工作，再到 arXiv、出版页面或作者主页取得原文。将两篇论文导入 Zotero，合并同一工作的重复版本，核对 DOI 和发表年份，导出 .bib，在两页短文中引用。优先引用已正式发表的版本；若使用的结论仅出现在预印本中，则注明该版本。模型提供的题名和引用必须能在原始来源中找到。

用 LaTeX、Overleaf 和 Zotero 整理研究

LaTeX 是用文本标记编写并编译文档的排版系统，适合公式、交叉引用、参考文献和论文模板。Overleaf 是浏览器中的 LaTeX 编辑与协作环境，可以编译预览 PDF；开始练习时不必先在本机安装完整 TeX 环境。Zotero 用于收集论文、整理笔记和管理书目信息，LaTeX 项目中的 .bib 文件则保存引用条目。

第一项练习：在 Overleaf 中新建项目，完成一份两页短文，包含标题、一个公式、一幅图、一张表、文内引用和参考文献。结合清华图书馆2025年 LaTeX 课件修改 .tex 与 .bib 文件；用 \label、\ref 维护图表编号，用 \cite{引用键} 插入引用，避免手动编排编号。中文文档可选用支持中文的模板，并按模板要求设置编译器。

论文写作采用目标会议或期刊的模板，日常汇报可以用 PowerPoint 或 LaTeX Beamer。每次交付都同时保存 PDF 与可编辑源文件；从 Zotero 或出版页面导入的引用，也要核对作者、题名、年份和 DOI。

04小规模免费 GPU 实验

先选择能正常访问的平台，完成一次小批次训练或推理，再扩大实验。以下免费条件按2026年9月的官方页面核对，实际可用 GPU 与额度以账户界面为准。

平台适合的入门任务免费条件与使用方式
Kaggle Notebooks公开数据上的图像分类、小模型微调、基线评测；预装环境可减少配置工作注册并完成平台要求的账户验证后，在 Notebook 设置中选择 GPU。官方使用说明给出按周重置的配额，通常为30小时，可能随供需调整；高峰期可能排队
Google Colab课程 Notebook、PyTorch 入门、少量推理与短时微调使用 Google 账户，在运行时类型中选择 GPU。免费资源动态分配，不保证具体型号和固定时数；会话可能因空闲或时限结束，需及时导出成果

第一次使用时，先确认 GPU 是否分配成功，再检查 PyTorch 是否识别 CUDA。将模型与输入放到同一设备；只修改运行时类型并不意味着程序已经用上 GPU。

尽量先在 CPU 上完成数据清洗和代码调试，GPU 只用于确实需要加速的步骤。缩小输入、batch size 和训练轮数，优先使用已有权重，定期保存 checkpoint。Kaggle 使用版本保存功能保留输出，Colab 将结果导出到获准使用的持久存储；临时运行目录不作为唯一备份。

免费 Notebook 按平台允许的方式使用。Colab 免费托管运行时不支持将 SSH 远程控制作为使用方式，不应套用实验室服务器的远程开发流程。长时间训练或受限医疗数据实验，使用导师安排的合适环境。

05用大模型完成一次科研实践

向工具交代清楚研究目标、已有材料、运行约束和期望成果。把较大的工作拆成可以逐项检查的任务，每完成一步，都保存结果并核对证据。

1. 读论文，确定要验证什么

先自己阅读摘要、方法图和核心实验，形成初步理解，再让工具帮助解释具体难点。例如：

根据这篇论文，说明研究问题、核心方法、关键实验和局限，标注对应章节、公式或表格。区分作者的结论和你的推测。用一个小例子解释核心公式，最后提出三个检查我是否理解的问题。

写一页论文笔记，回答：输入输出是什么？方法改变了什么？哪项实验支持主要结论？哪些问题尚未验证？引文、公式和数字都应回查原文，工具推荐的相关论文也要核实。准备作为代码基础的论文，需要进一步理解其实现细节。

2. 读代码，跑通最小流程

把论文和作者仓库提供给工具，先找到实际执行路径：

阅读 README、环境配置和主要代码，定位数据加载、训练、推理与评测入口，标明文件位置。追踪一个 batch 的张量形状，说明代码与论文的对应关系。列出所需数据、权重、显存和缺失条件，给出最小运行方案。

核对方案后，在独立环境中运行一个小批次，检查数据、损失和输出，再执行选定的正式实验。查看每次代码修改的差异；依赖调整和实现偏差都应写入记录。

复现前先确认材料能否获得。例如，BenchX 仓库 [20] 提供代码和数据处理说明，原始数据需要另行获取；CMM 仓库 [21] 提供评测资料，并列有数据使用限制。条件尚未具备时，可以先阅读代码、用模拟数据检查接口，或与导师更换任务。

3. 做对照实验，检验一个假设

基线是用来比较的参照方法。先保存基线结果，再确定要改变的因素，以及什么结果会支持或推翻自己的判断。例如：

基线已经跑通。我想比较两种模型在不同标注量下的表现。请固定患者划分、评价指标和训练预算，设计两个标注比例的实验。两个方法使用相同的训练子集，验证集和测试集保持不变。列出对照关系，再编写配置和运行脚本。

先小规模检查，再按预算扩大实验。用验证集选择超参数和阈值，在方案确定后评估测试集。若结果出现异常提升，先排查数据泄漏、标签处理和指标实现。

统一评测可从 BenchX [20] 支持的一个任务入手，确认两种可用权重，核对预处理和标签顺序，再进行比较。小批次运行用于检查流程，完整结论需要对应规模的正式评测。

4. 分析结果，写清证据和局限

将真实日志和预测文件交给工具，要求它从这些材料生成图表：

只使用提供的日志和预测文件整理结果，标注样本量、随机种子与运行配置，保留失败实验。区分观察结果、解释假设和尚未验证的结论。检查错误案例，指出最值得继续验证的问题。

图表由脚本生成，并保留原始数据。涉及随机训练时，在预算允许范围内使用多个种子、报告波动；只有一次运行则明确注明。没有稳定改善也应如实报告，并解释当前证据的局限。

让工具协助整理材料、润色论证和检查引用。最终需要自己解释关键代码，核对至少一个核心指标，并讲清一个失败案例。

5. 保存项目规则与实验记录

把研究目标、数据路径、环境、运行命令、评价指标和预算写入项目规则，减少每次对话重复说明。Codex 使用 AGENTS.md；Claude Code 使用 CLAUDE.md，也可以在其中写入 @AGENTS.md 共享同一份规则。具体配置见 Codex 文档和 Claude Code 文档。

文末提供了可直接填写的模板。一个流程反复使用并验证有效后，可以将其整理为 Skill，例如论文笔记、复现检查或实验结果汇总。

06四周入门安排

以下节奏适合规划第一个项目，可根据基础、课程安排和实验条件调整。

阶段任务阶段成果
第1周建立 Linux 开发环境和 Git 仓库，完成小型训练与评估，练习使用科研助手可运行示例与 README，能解释数据流和损失
第2周精读两篇论文，梳理作者代码，确认数据、权重和算力两篇笔记与范围明确的复现计划
第3周复现一篇论文中的一个任务，核对与原文的设置差异配置、日志、预测及结果对照
第4周完成一组对照或消融实验，分析错误案例并汇报一个有证据支持的判断、简短报告和可重跑材料

使用现成权重完成评估时，说明完成的是推理或评测复现；仅运行小规模配置时，说明完成的是小规模验证。没有 GPU 时，也可以先做代码追踪、获准使用的预测文件评估和指标核验，再与导师安排后续训练。

07实验与科研规范

医学数据按使用协议处理，检查患者级隔离，避免同一患者的信息跨训练与测试。真实病历、受限影像和未公开数据，只有在明确获准后才能发送到外部模型服务；密钥不应写入代码或实验报告。

公平比较需要一致的数据划分、预处理和评价方式，并记录模型权重与训练预算。分类、定位和生成任务应选择适合各自目标的指标；报告与对话还需要检查事实是否有证据支持。

每次实验保存代码版本、环境、配置、运行命令、原始日志和预测。保留负结果，不通过改变标签、划分或指标来追求更好数字。另一个模型给出相同答案，也不能代替原文核对或实验验证。

结论应与证据范围相符。小样本、模拟病例或单个数据集上的结果，都有相应局限。涉及医学含义的解释，应结合证据并请具备相应专业知识的人核验。

08整理成果与交流

1. 文献与实验报告

提交一份 PDF 报告，并附可编辑源文件。正文建议6至10页，参考文献和实验日志可另附；以讲清工作为准。报告按以下内容组织：

部分具体要求
基础理解不超过2页。围绕自己的任务解释数据、模型、损失和指标；用一个例子说明，不拼贴教材定义
两篇论文精读每篇说明研究背景、具体问题、动机与贡献、方法图或关键公式、核心实验及局限；至少提出一个有依据的疑问
一项代码复现写明论文版本、代码提交号、Linux/Python/框架环境、数据划分、权重、运行命令、超参数和评测设置；列出原文与自己结果的对照表
对照或消融实验说明假设、基线、改变的因素和控制条件；报告样本量、随机种子、主要指标和至少一个失败案例；解释偏差与局限
个人思考与下一步写清学会了什么、哪些问题仍不理解，提出一个可以执行的后续实验
参考文献与 AI 使用文内引用与文末条目一一对应；说明 AI 协助的步骤、关键修改、纠正的错误及人工核验方式

复现未达到原文结果时，按数据、预处理、权重、训练预算和实现差异逐项分析。未运行的实验明确标注，不用推测数字填补结果表。背景和方法要讲清，实验部分也应足以让读者判断结论是否成立。

2. 代码与复现材料

提交代码仓库链接或源码压缩包，至少包含以下材料：

  • README.md：研究问题、目录说明、数据获取条件、环境安装、从数据准备到训练/推理和评测的完整命令，以及当前完成范围。
  • 环境与配置文件：如 requirements.txt 或 environment.yml、训练配置和固定的数据划分标识；保存代码版本及随机种子。
  • 运行与分析脚本：提供最小验证命令、正式实验命令和作图脚本，使用可修改的路径配置，不依赖个人机器的硬编码路径。
  • 结果材料：主要日志、逐样本预测或合规的汇总结果、指标表与图表。大权重提供合法下载地址及版本信息，受限数据不随仓库分发。

提交前，从一个新建环境按 README 重跑最小示例，确认其他人能找到所需材料。代码截图可以解释局部实现，但必须同时提供可运行代码。

3. 文献与实验汇报

准备10至12页幻灯片，汇报约10分钟，并预留讨论时间。建议按“问题与背景1至2页、两篇论文的方法和关键证据4页、自己的复现与对照3至4页、局限和下一步1页”组织，可按内容调整。

每页只保留一个主要信息，方法图、结果表和对照样本应能独立看懂。图表有标题、坐标、单位和必要图例；引用或改绘的图表在当页底部标明来源。中文和英文分别保持一致字体，字号以投影可读为准；不依赖动画呈现关键内容。提交 PDF，同时保留 .pptx 或 Beamer 源文件。

汇报时准备回答：为什么研究这个问题？方法相对基线改变了什么？一次前向传播的数据形状如何变化？为什么选这个指标？哪项结果支持结论？AI 写出的哪些关键部分经过了你的检查？

4. 提交与每周沟通

文件统一命名为 姓名_方向_材料类型_日期，例如 张三_医学基础模型_报告_20260930.pdf。提交报告 PDF、幻灯片 PDF、源码或仓库链接，并附3至5行摘要：完成了什么、主要发现、尚存问题和希望讨论的内容。通过导师指定渠道提交；联系信息见周阳老师主页，共享链接应保证接收人可访问。

每周沟通用一页笔记说明本周完成的任务，附实验编号、图表或代码链接；记录阻塞问题及已尝试的方法，列出下周1至2项具体工作。遇到报错时，提供环境、完整错误信息和最小复现步骤；涉及密钥或受限数据的内容先移除。
